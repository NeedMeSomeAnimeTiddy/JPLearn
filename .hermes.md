# JPLearn — Hermes Project Context

Hermes: when operating anywhere inside this repository, you are in **JPLearn development mode**. This is a Japanese-language learning desktop app — Electron + React 19 + TypeScript frontend, Python backend with FSRS v4.5 SRS scheduling logic. Scope your behavior to this repo and keep unrelated context (homelab, Proxmox, Crafty, Windows Desktop, other projects) out unless the user explicitly asks for it.

## Full rules live in AGENTS.md
This repo ships a detailed `AGENTS.md` at the root (architecture, commands, layer rules, subagent types, validation order). **Read `AGENTS.md` before doing implementation work here** — it is the authoritative dev guide. This `.hermes.md` only adds Hermes-specific scoping on top of it; do not treat it as a replacement.

## Hermes-specific notes
- No profile switch needed. You run under the `default` profile. This file provides the contextual boundary that a separate profile would otherwise give — it scopes Hermes to JPLearn whenever cwd is anywhere under this repo (including subdirectories, which AGENTS.md's cwd-only load does not cover).
- Stack at a glance: `domain/` (pure SRS logic, no I/O) · `data/` (SQLite persistence + Japanese text normalization) · `electron-frontend/` (React 19.2 UI + Electron main process + IPC bridge) · `tests/` (pytest for Python, vitest for frontend).
- `main.py` is deprecated — raises `RuntimeError`. Use the Electron frontend.
- Validate in order: lint → typecheck → test. `npm run lint` (oxlint, must pass with 0 warnings) and `npm run build` after meaningful edits. Python: `python -m pytest -q`. Layer-boundary check: `python scripts/arch_check.py`. Respect the per-layer instruction files under `.github/instructions/`.

## Scope guard
If a task touches the user's homelab, Proxmox, Crafty Controller, or Windows Desktop instead of this repo, that is **out of scope** for this file — fall back to general/default context and do not assume JPLearn conventions apply there.

## Security
Neither this file nor Hermes profiles are a filesystem sandbox. On the default `local` backend you still have full access to the user's home, secrets, SSH keys, and `.env` files across all profiles. Treat this scoping as behavior guidance only, never as a security boundary. Handle credentials per the user's existing security expectations.
